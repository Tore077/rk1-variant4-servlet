## Б бөлімі. Теориялық сұрақтар

### 1. GET және POST әдістерінің айырмашылығы неде? Пароль жіберу үшін қайсысы қауіпсіз және неге?

| | GET | POST |
|---|---|---|
| Деректер қайда | URL-де (query string): `/login?user=a&pass=123` | Сұраныс денесінде (body) |
| Көрінуі | Адрес жолында, браузер тарихында, бетбелгіде, сервер логтарында көрінеді | Адрес жолында көрінбейді |
| Көлемі | URL ұзындығымен шектелген (шамамен 2–8 КБ) | Шектеуі өте үлкен, файл да жіберуге болады |
| Кэш, бетбелгі | Кэштеледі, бетбелгіге сақталады | Кэштелмейді, бетбелгіге сақталмайды |
| Мақсаты | Деректерді алу (іздеу, сүзу) — қайталауға қауіпсіз | Деректерді жіберу, өзгерту (тіркелу, тапсырыс) |
| Servlet әдісі | `doGet()` | `doPost()` |

**Пароль үшін POST қауіпсіз.** GET-те пароль URL-ге жазылады, сондықтан ол браузер тарихында, бетбелгіде, сервер мен прокси логтарында және Referer тақырыбында қалып қояды, оны иықтан қарап та көруге болады. POST-та пароль сұраныс денесінде жіберіледі, бұл жерлерде сақталмайды.

Бірақ POST өздігінен шифрламайды: дене ашық мәтін күйінде жүреді. Сондықтан нақты қауіпсіздік үшін **POST + HTTPS** қолдану керек, ал серверде парольді хэш (мысалы, bcrypt) түрінде сақтау қажет.

### 2. forward() және sendRedirect() әдістерінің айырмашылығын мысалмен түсіндіріңіз.

| | `forward()` | `sendRedirect()` |
|---|---|---|
| Қайда орындалады | Серверде, контейнер ішінде | Браузер арқылы (клиент жағында) |
| Сұраныстар саны | 1 сұраныс | 2 сұраныс (302 жауап → браузер жаңа адреске барады) |
| URL | Адрес жолы өзгермейді | Адрес жолы жаңа адреске ауысады |
| request атрибуттары | Сақталады (`request.setAttribute` келесі бетке жетеді) | Жоғалады (жаңа request) |
| Қайда бағыттауға болады | Тек осы веб-қосымшаның ішіне | Кез келген адреске, басқа сайтқа да |
| Жылдамдығы | Жылдамырақ | Баяуырақ (қосымша айналым) |

Мысал — `forward()`: Servlet есептеп, нәтижені JSP-ге береді, URL өзгермейді:

```java
request.setAttribute("count", 2);
request.getRequestDispatcher("/result.jsp").forward(request, response);
```

Мысал — `sendRedirect()`: тіркелу формасы сәтті сақталғаннан кейін басқа бетке жіберу (Post/Redirect/Get), F5 басқанда форма қайта жіберілмейді:

```java
// деректерді сақтағаннан кейін
response.sendRedirect(request.getContextPath() + "/success.html");
```

Қысқасы: бір сұраныс ішінде деректерді беру керек болса, `forward()` қолданылады. Пайдаланушыны жаңа адреске жіберу керек болса (POST-тан кейін, логиннен кейін, сыртқы сайтқа), `sendRedirect()` қолданылады.

## В бөлімі. Практикалық тапсырма — «Қызығушылықтарыңыз»

Формада 4 checkbox бар: Музыка, Спорт, Кітап, Кино (`name="interest"`). Servlet:
- `getParameterValues("interest")` арқылы барлық таңдалған мәндерді оқиды;
- оларды « • » белгісімен бөліп, санын көрсетеді: «Таңдалды: 2 — Музыка • Спорт»;
- ештеңе таңдалмаса (`getParameterValues` → `null`), «қызығушылық таңдалмады» деп жазады;
- нәтиже бетінде таңдалған белгілер сақталады.
